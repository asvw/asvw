Fixes to Kubernetes, found while live validating CKA labs end to end against the 1.37 code and the docs. Merged upstream in October 2026:

- [kubernetes/website#58356](https://github.com/kubernetes/website/pull/58356). The kubeadm implementation details page said the API server's kubelet client certificate is in the `system:masters` group. kubeadm has written no group in that certificate since v1.37, so the sentence is gone.
- [kubernetes/website#58390](https://github.com/kubernetes/website/pull/58390). The same page's TLS-bootstrapping steps did not name `kubeadm:apiserver-kubelet-client`, the ClusterRoleBinding through which kubeadm grants the API server's kubelet client access to the kubelet API since v1.37. The step is added.
- [kubernetes/website#58373](https://github.com/kubernetes/website/pull/58373). The etcd task page's restore into a new data directory left the cluster on the old data. The step that points etcd at the new directory sat in the deprecated `etcdctl` tab only, and on a cluster that kubeadm manages the next `kubeadm upgrade` put etcd back on the old directory. The step now sits below both tabs, and the page says to set `etcd.local.dataDir` in the `kubeadm-config` ConfigMap, so that the restore survives the next upgrade.
- [kubernetes/examples#598](https://github.com/kubernetes/examples/pull/598). The guestbook example did not work. Its Redis leader image no longer pulls on containerd 2.1 and later, and its frontend looked up Service names the manifests did not create. The image is pinned, the Services carry the image's names, and an e2e test checks a write and a read through the frontend.
